# Open-Meteo: AUTO для температуры Цхинвала — 24.11.2026

Для обоих запросов — архивной температуры и прогноза — добавлен режим **AUTO**.
Сначала используется прямой доступ. При тайм-ауте, ошибке соединения, HTTP 403/408/425/5xx
из поддерживаемого списка или ответе не в JSON выполняется повтор через резервный маршрут.

Если переключение потребовалось при загрузке архива, прогноз в том же запуске тоже
запрашивается через прокси. Если архив уже получен напрямую, а сбой произошёл на прогнозе,
повторяется только прогноз. После переключения используется один прокси/SSH-туннель до
конца сбора; после завершения или ошибки ресурсы закрываются. Следующий запуск снова
начинается с прямого доступа.

## Минимальная настройка

Добавьте в существующий `.env`:

```dotenv
TSKHINVAL_NETWORK_MODE=auto
TSKHINVAL_DIRECT_ATTEMPTS=1
# Пусто — резервный маршрут создаётся автоматически по общим SSH-настройкам VPN.
TSKHINVAL_PROXY_URL=
TSKHINVAL_TUNNEL_MODE=dynamic
```

Эти значения действуют и по умолчанию. Если `TSKHINVAL_PROXY_URL` уже был заполнен,
он будет использоваться как резервный прокси. Чтобы использовать собственный SSH-туннель
вместо ранее настроенного Hiddify, оставьте `TSKHINVAL_PROXY_URL` пустым.

Второй вариант — явно указать адрес доступного HTTP/SOCKS-прокси. Тогда SSH не используется:

```dotenv
TSKHINVAL_NETWORK_MODE=auto
TSKHINVAL_PROXY_URL=socks5h://proxy.example.net:1080
```

Адрес в примере замените своим. Локальный Hiddify и порт 12334 не являются обязательными.

## Режимы

| `TSKHINVAL_NETWORK_MODE` | Поведение |
|---|---|
| `auto` | Прямой доступ, затем при сетевой/HTTP-ошибке резервный маршрут |
| `direct` | Только прямой доступ; заданный прокси и SSH не используются |
| `proxy` / `vpn` | Сразу резервный маршрут: явный прокси либо собственный SSH-туннель |

В AUTO по умолчанию выполняется одна сетевая попытка напрямую.
`TSKHINVAL_DIRECT_ATTEMPTS` регулирует число таких попыток. Число повторов через прокси
задаётся прежним `TSKHINVAL_HTTP_ATTEMPTS` (по умолчанию 3).
`TSKHINVAL_CONNECT_TIMEOUT` и `TSKHINVAL_READ_TIMEOUT` действуют на оба маршрута.

Ошибки параметров/ключа/адреса (HTTP 400, 401, 404, 422) и ограничение запросов 429 не
вызывают смену маршрута. Явная пауза `Retry-After` при переключении сохраняется.
Если JSON получен, но в нём нет необходимых суток, неверные единицы/часовой пояс или
пустая температура, это ошибка данных: такой ответ не принимается как успешный и
не вызывает повтор через другой IP.

## SSH без отдельного запуска Hiddify

Если `TSKHINVAL_PROXY_URL` пуст, Paramiko создаёт временный SOCKS-прокси поверх SSH.
Внутренний локальный порт выбирается автоматически. При исправном прямом доступе
SSH-соединение не создаётся, SSH-ключи не проверяются.

Все реквизиты SSH берутся из общего блока `VPN_SSH_*` в `.env`. Проверка ключа сервера сохраняется. Полный перечень параметров — в `.env.example`.

В `dynamic` адреса Open-Meteo разрешаются на SSH-сервере (`socks5h`). Если требуется
использовать прокси-службу самого VPN-сервера, выберите `forward` и задайте её порт
в `VPN_REMOTE_PROXY_PORT` и протокол в `VPN_REMOTE_PROXY_SCHEME`.

## Сохранение и отправка

Формат CSV, регион, единицы, интервалы истории/прогноза и датированные имена вложений
сохраняются. Обработка по-прежнему идёт через DataGateway. Системные HTTP_PROXY/HTTPS_PROXY
не подменяют прямую попытку; HTTPS-сертификаты проверяются. API-ключ маскируется в логах.

Если оба маршрута не работают, прежний рабочий CSV не заменяется. Процесс сообщает
предупреждение по существующей схеме уведомления об ошибке; остальные задачи продолжаются,
завершённый общий проход возвращает 0.

Общий механизм находится в `common/auto_http.py`. В `common/http_client.py` HTTP-ошибке
добавлен статус для выбора маршрута; её тип остаётся наследником SourceError.
Для прочих источников прежний выбор прямого/явного прокси не меняется.

## Установка

Замените файлы патча и добавьте нужные настройки в существующий `.env`.
Новых зависимостей нет. `main.py`, `ENABLED_PROCESSES` и cron этой правкой не меняются.
На ноутбуке запускайте прежний `main.py`.

На сервере после замены файлов пересоберите образ:

```bash


cd /home/vologzhaninov_as/projects/morning_upload
docker build --progress=plain -t morning_upload:latest .


```

## Проверка реализации

Получены и разобраны реальные ответы Open-Meteo: 15 суток истории и существующий
прогнозный горизонт (по умолчанию сегодня и 7 следующих суток, всего 8 строк прогноза).
Проверяется итог из 23 строк в прежних шести столбцах и MIME-имя CSV-вложения с датой.

В 21 контролируемом тесте проверены: оба прямых запроса; переключение при сбое архива
и при сбое только прогноза; HTTP 403/5xx; HTML вместо JSON; статический прокси;
принудительные режимы; общие параметры SSH; повторы и Retry-After;
сохранность старого CSV при сбое обоих маршрутов; отсутствие переключения при ошибке
параметров/квоте/неполных данных; закрытие клиентов/туннеля; маскирование API-ключа.

Проверка переходов выполняется с тестовыми HTTP/SMTP и SSH-подключениями. Реальные
письма не отправлялись, подключения к вашему VPN-серверу не выполнялись.
