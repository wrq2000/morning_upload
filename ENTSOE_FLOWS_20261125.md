# Физические перетоки ENTSO-E — File Library (25.11.2026, МСК)

Ежедневный процесс `ENTSO-E` в `main.py`, модуль `processes/entsoe_flows/`.
Вместо 144 отдельных запросов REST API используются месячные CSV из File Library,
папка `PhysicalFlows_12.1.G_r3`, через `entsoe-py==0.8.1` (как в первоначальном скрипте).

## Настройка

Установить `entsoe-py==0.8.1` в интерпретатор проекта (PyCharm / Python Packages),
если пакет отсутствует. Добавлен в `requirements.txt`. Остальные зависимости не изменены.
В рабочем `.env` указать `ENTSOE_USERNAME` (email аккаунта) и `ENTSOE_PWD` (пароль).
`ENTSOE_API_TOKEN` больше не используется, можно оставить или удалить.
`ENTSOE_LOOKBACK_DAYS=10` — число завершённых календарных суток до даты запуска по МСК (1–31).
`ENTSOE_READ_TIMEOUT=180` — тайм-аут чтения ответа, `ENTSOE_CONNECT_TIMEOUT=10` — подключения.
`ENTSOE_HTTP_ATTEMPTS=3` — число попыток временно неудачной сетевой операции.
`ENTSOE_PROXY_URL` — явный прокси при необходимости (TLS проверяется).
`ENTSOE_SUCCESS_RECIPIENTS` / `ENTSOE_ERROR_RECIPIENTS` — адреса или общие настройки рассылки.
Отключение процесса: закомментировать `("ENTSO-E", "run_entsoe_flows")` в ENABLED_PROCESSES.

## Получение и агрегация

Одна авторизация, один запрос списка файлов, одна загрузка ZIP на необходимый UTC-месяц.
Обычно достаточно 1–2 месячных файлов при окне 10 дней. 25.11.2026 — только ноябрь,
1.12.2026 — также только ноябрь, 2.12.2026 — ноябрь и декабрь.
При выборе месяцев учитываются границы локальных суток всех стран отправления.
При каждом запуске нужные месяцы скачиваются заново, чтобы учитывать ревизии данных.
CSV читается непосредственно из ZIP в памяти порциями по 100 000 строк, без распаковки на диск.
Внутрисуточные данные, исходные CSV и ZIP не отправляются и не сохраняются в БД.
Список из 75 пар (144 уникальных направления), исходные EIC и часовые пояса сохранены в `config.py`.
Не подменяем EIC стран торговыми зонами и не суммируем дубли.

Поля исходного CSV: DateTime(UTC), ResolutionCode, OutAreaCode, InAreaCode, Flow[MW], UpdateTime(UTC).
Для каждой пары EIC и UTC-времени оставляем последнюю ревизию по UpdateTime(UTC).
При одинаковом времени обновления и конфликтующих значениях такие сутки не публикуются.
`ResolutionCode` явно определяет длительность каждой исходной точки: 15/30/60 мин.
Переходы гранулярности в течение суток и между полными сутками фиксируются в журнале.
Пропуски между точками не считаются интервалами и не заполняются нулями.
Сутки с неполным покрытием, конфликтующими перекрытиями, неизвестной гранулярностью исключаются.
Среднее — взвешенное по длительности интервалов (сетка 15 минут), учитывается DST 23/24/25 часов.
Формула gas_ecv = flow_mw * 24 * 2 / 10750 сохранена с фиксированным 24 даже при DST.

## Выход и совместимость

`output/entsoe/entsoe_flows.csv`, UTF-8 BOM, разделитель `;`, датированное вложение.
Колонки без изменений: date, country_from, country_to, flow_mw, gas_ecv, coverage_minutes,
expected_minutes, resolution_min, resolution_max, source_points_count.
`source_points_count` — число исходных точек после удаления ревизий, а не число искусственных 15-минутных интервалов.
Максимум 1440 строк при окне 10 дней. Пропуски указаны в журнале и письме; частичный результат
отправляется, если есть хотя бы одни полные сутки. Ошибка скачивания/структуры прекращает сбор.
`gas_data_duty` и таблица `entsoe_flows` не требуют изменений.
Префикс темы `134101`, общий механизм CSV и отправки сохранены.

## Проверка

Тесты используют искусственные ZIP с TSV согласно официальному описанию формата.
Проверены переходы месяцев, DST, 15/30/60 минут, смешанные сутки, дубли, пропуски,
фильтрация порциями и единичная загрузка каждого месяца. Реальный File Library, учётные данные,
скорость сетевой загрузки и SMTP не проверялись. Сравните несколько направлений с прежней выгрузкой.
