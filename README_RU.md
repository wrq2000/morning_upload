# Morning Upload

Обновление 17.11.2026: поддерживается новая разметка календаря и объявлений
Next.js, а также прежняя разметка. Описание и порядок установки исправления:
[UPDATE_SITE_20261117.md](UPDATE_SITE_20261117.md).

Обновление 18.11.2026: словарь расширен по новым сессиям. Если перевода нет,
исходный текст сохраняется в CSV и выводится WARNING; сбор и рассылка продолжаются.
[UPDATE_TRANSLATIONS_20261118.md](UPDATE_TRANSLATIONS_20261118.md).

Ежедневное приложение запускает независимые процессы БелАЭС, Tuz Gölü,
EPİAŞ и УЭБ. Существующий запуск сохранён: пользовательский cron в 08:00 МСК
→ `run.sh` → Docker → `main.py`. Единственная точка входа Python — `main.py`,
без аргументов. Параметры источников, почты и сети читаются из `.env`,
состав запускаемых задач задаётся в `ENABLED_PROCESSES` (main.py).

Начальная история УЭБ уже загружена в БД отдельным загрузчиком. Этот процесс
продолжает сбор результатов экспорта природного газа, сохранение CSV и рассылку.

## Окно загрузки

```dotenv
UEEX_RECHECK_DAYS=14
```

Каждый запуск проверяет текущий день и 13 предыдущих календарных дней.
11 ноября это 29 октября–11 ноября, 12 ноября — 30 октября–12 ноября.
Окно применяется к календарю, объявлениям и страницам результатов.
Оно действует при первом и повторных запусках, после перезапуска Docker
и без локального состояния. Длительность перерыва его не расширяет.

Размер окна задаётся в `.env` одной переменной. `UEEX_START_DATE=2026-10-15`
остаётся нижней границей допустимых дат; пустой `UEEX_END_DATE` означает
текущую дату МСК. Значения по умолчанию — в `processes/ueex/defaults.env`;
для переопределения их имён в `.env` используется префикс `UEEX_`.

История до начала окна сохраняется в CSV из локального состояния без запросов
к сайту. Сессии внутри окна обновляются по ID и объединяются с историей
без дублей. Без локального состояния CSV содержит только данные окна.
Для сохранения накопленного CSV используйте прежний постоянный output.

Окно без торгов считается успешной проверкой. С сохранённой историей остаётся
накопленный CSV; без неё создаётся CSV с заголовками и без строк.
При ошибке HTTP/разбора предыдущий CSV сохраняется и не отправляется как новый.
Успешные промежуточные ответы позволяют продолжить прерванный запуск.

CSV сохраняет 44 английских заголовка, русский текст значений и исходные
названия компаний. `actual_cost = sold_volume × price_avg` вычисляется
через Decimal без дополнительного округления.

Известные фразы переводятся, неизвестные сохраняются в исходном виде с WARNING
в журнале. Неизвестное название документа сохраняется целиком. Повторяющиеся
предупреждения кэшируются в пределах процесса запуска; отсутствие перевода
не препятствует публикации CSV и отправке письма.

## Ежедневное письмо

Указываются проверенное окно, время текущей и предыдущей успешной проверки
с отправленным отчётом, новые сессии и количество дат с такими торгами.
Сессии считаются по номеру торгов независимо от объёма: нулевые продажи
и даже пустой список позиций опубликованной сессии учитываются как торги.
Показываются сессии с продажами/без продаж, изменения прежних результатов
и исторические даты, результаты которых обнаружены позднее.

Если новых сессий нет: «В проверенном окне новых торгов не обнаружено
(по опубликованным данным УЭБ)». Если в календаре есть новые объявления
без опубликованных результатов, это указывается отдельно вместо вывода
об отсутствии торгов. Первый отчёт явно помечается как первый для периода.

Точка сравнения сохраняется после подтверждения отправки всем получателям.
Ошибка SMTP не приводит к потере уведомления о новых торгах. Повтор той же
версии CSV и снимка сессий в тот же московский день отправляется только
оставшимся получателям. Новый день формирует письмо даже при неизменном CSV.
Существующие файлы состояния поддерживаются.

## Задачи, VPN и почта

Единственная точка включения и отключения задач — `ENABLED_PROCESSES` в main.py.
В списке явно указаны БелАЭС, Tuz Gölü, EPİAŞ и УЭБ; Argus и DESFA
приведены закомментированными строками. Для отключения задачи закомментируйте
её строку, для включения — раскомментируйте. Для запуска одной УЭБ оставьте
активной только строку `("УЭБ", "run_ueex")`.
Выбор задач через переменные окружения удалён. В Docker изменения main.py
вступают в силу после пересборки образа. Сохранены параллельный запуск
выбранных задач и код завершения 0/1.

Подтверждённый маршрут УЭБ: Paramiko → SSH vdska → интернет.
В `.env.example` приведены адрес 185.28.175.2:22, root, путь к Ed25519-ключу
и доверенный SHA256-отпечаток сервера. `UEEX_TUNNEL_MODE=dynamic` создаёт
SOCKS5 внутри контейнера на автоматически выбранном порту. `run.sh` монтирует
`$HOME/.ssh` хоста в `/root/.ssh` контейнера только для чтения.
Приватный ключ хранится на gpu-server; публичный разрешён на vdska.
При пустом отпечатке требуется доверенный ключ в known_hosts.

Режим `forward` пробрасывает проверенный удалённый порт прокси, `none`
использует `UEEX_PROXY_URL`. Для УЭБ прокси обязателен; при отказе прямой
доступ не используется. Другие процессы используют свои прежние маршруты.

Основная почта настраивается через `SMTP_*`, резервная — `SMTP_BACKUP_*`.
Все шесть процессов используют `common/mailer.py`: УЭБ и EPİAŞ — класс
MailSender, остальные — функцию send_mail, создающую тот же MailSender.
Поддерживаются starttls/ssl, отдельные USERNAME/FROM и пароли приложений.
Яндекс и Google проверены пользователем. При отказе основного резервному
передаются только ещё не принятые получатели. Подтверждение SMTP означает
приём сервером отправки. Адресаты УЭБ: `UEEX_SUCCESS_RECIPIENTS`, либо `RECIPIENTS`.
Отдельный список `EPIAS_RECIPIENTS` сохранён. В Docker env-file реквизиты
указываются без внешних кавычек.

## Постоянные данные

`UEEX_OUTPUT_DIR=output/ueex` содержит CSV, состояние исходных данных,
промежуточный прогресс, ожидание после HTTP 429 и журнал подтверждённых писем.
Этот каталог сохраняется между запусками контейнера и при обновлении.
`run.sh` поддерживает выбор образа `MORNING_IMAGE` и каталога `MORNING_OUTPUT_DIR`.
Из PyCharm запускается main.py без аргументов, настройки — в `.env`.

После завершения диагностики тестовые модули, CLI и демонстрационные
запуски удалены. Порядок обновления сервера — `deployment/DEPLOYMENT_RU.md`;
результаты исходного сравнения — `deployment/SERVER_COMPARISON_RU.md`.
Пароли, ключи, журналы и runtime-состояние в архив не включаются.

## Изоляция источников и частичные результаты УЭБ

Ошибка отдельной задачи не отменяет остальные процессы. УЭБ продолжает сбор после
ошибки одной даты, объявления или аукциона; неполная выгрузка и письмо явно помечаются,
а основной CSV последнего полного сбора сохраняется.
См. [UEEX_RESILIENCE_20261124.md](UEEX_RESILIENCE_20261124.md).


## Завершение с предупреждениями

Обработанные сбои источников и частичный сбор отражаются в предупреждениях;
завершённый общий проход возвращает 0. Состояние полноты данных остаётся отдельным
от кода завершения. См. [WARNING_EXIT0_20261124.md](WARNING_EXIT0_20261124.md).
