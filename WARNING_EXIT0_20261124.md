# WARNING и код завершения 0 — 24.11.2026

Завершённый общий проход теперь возвращает **0**, даже если один или несколько источников
не получили данные либо завершились частично. Предупреждения остаются в итогах и логах.
Обработанные сбои УЭБ, диспетчера и обёрток процессов выводятся как **WARNING**.

Статус данных сохраняется отдельно от кода ОС: `success/all_success` остаются false
для неуспешного источника, `partial` остаётся true для частичной выгрузки. Флаги успешного
сбора и последнего полного отправленного отчёта не сдвигаются из-за кода завершения 0.
Последний полный CSV сохраняется, частичный CSV и письмо помечаются как прежде.

Критическая ошибка самого приложения вне обработки источников по-прежнему возвращает 1,
а прерывание пользователем — 130. Обычный сценарий из вашего лога завершается кодом 0.

## Что означает Empty member

Проверена актуальная страница результатов и её скрипт:

`https://bets.ueex.com.ua/public/js/PositionList.js?v=1.5.0.0152`

Файл побайтно совпадает с сохранённой версией от 23.11.2026. Скрипт страницы продолжает
использовать тот же публичный обработчик `Handler/Action?name=jResults` и те же параметры.
Признаков смены адреса или формата запроса результатов не обнаружено.

Повторена последовательность запросов страницы: загрузка страницы, `jGetFieldPropList`,
затем `jResults`. Запросы к API получают HTTP 200, но возвращают объект `Message` с
`PrepareAuction … LogCollection.Getdata … GetItemById … Empty member`.
Ошибка затрагивает и запрос свойств полей, и запрос результатов.

HTTP 200 подтверждает получение HTTP-ответа; успешных данных `info/rows` в этом ответе нет.
Судя по именам методов, сбой возникает при получении элемента внутренней коллекции данных
сервера. По публичному сообщению нельзя установить, связана ли первопричина с данными,
кешем или серверным кодом. Установить её могут сотрудники биржи по серверным журналам.

В вашем запуске все восемь запрошенных аукционов вернули `Message`, поэтому свежих позиций
в частичной выгрузке 0. Сохранённые семь снимков остаются в JSON-состоянии и не превращаются
в якобы заново проверенные данные. Возобновление свежей выгрузки зависит от восстановления API.

Новые настройки `.env` и зависимости не требуются. Состояния удалять не нужно.
В PyCharm запускается прежний `main.py`.

Для сервера пересоберите Docker-образ после замены кода:
