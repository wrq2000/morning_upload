# Дата в имени почтовых CSV-вложений — исправление 23.11.2026

Правка относится к **именам вложений в письмах**. Рабочие файлы в `output/` сохраняют
постоянные имена, чтобы не менять накопление истории, состояния и существующие настройки.

Для всех процессов на основе `CsvMailProcess` датирование теперь включено по умолчанию,
включая Цхинвал. УЭБ сохраняет свой механизм отправки датированной копии.

Примеры имён, которые получатель увидит в письме:

- `spimex_PCX1UGU036F_2026-11-23_080001_123456.csv`
- `ueex_gas_export_2026-11-23_080001_123456.csv`
- `temperature_tskhinval_2026-11-23_080001_123456.csv`
- `eurostat_gas_balance_2026-11-25_080001_123456.csv`

Используется дата создания выгрузки в MSK; время и микросекунды различают повторные
выгрузки. Дата берётся из mtime рабочего CSV. Содержимое CSV не меняется, для отправки
создаётся временная копия с новым именем.

## Что было обнаружено

В проверенной исходной версии архива (версия 17) СПбМТСБ, УЭБ и Eurostat уже отправляли
датированные вложения. Цхинвал оставался без даты — этот пропуск исправлен. Готовые
письма проверены через реальный `MailSender`, сериализацию MIME и обратное чтение
`Content-Disposition/filename` — не только по имени временного файла. Проверены
все четыре источника, неизменность байтов CSV и резервный SMTP. Реальные письма
в ходе проверки не отправлялись, сетевые операции SMTP были заменены тестовым приёмником.

Отсутствие даты у первых трёх процессов в полученных вами письмах текущим кодом
не воспроизвелось. Возможны запуск прежней версии/образа или просмотр письма,
отправленного до обновления. Без логов конкретного запуска причину подтвердить нельзя.

Теперь общий mailer перед отправкой пишет в лог точное MIME-имя:

```text
common.mailer | Вложение: temperature_tskhinval_2026-11-23_080001_123456.csv (1.25 КБ)
```

## Установка

Патч включает общий механизм CSV-вложений, общий mailer и текущие точки отправки
СПбМТСБ, УЭБ и Eurostat, чтобы его можно было применить вместе с предыдущей правкой
датирования. Цхинвал использует обновлённый базовый класс. Для полной актуальной
редакции, включая VPN БелАЭС, используйте полный архив `morning_upload.zip`.

Распакуйте патч поверх **того проекта, из которого действительно запускается приложение**.
Ваш `.env` в патч не включён; новые настройки для датирования не требуются.

Если запуск идёт напрямую из PyCharm, достаточно заменить файлы и заново запустить
`main.py`. Если запуск идёт через Docker, замены файлов на хосте недостаточно:
необходимо пересобрать образ из этого же каталога.

Сборка на сервере:

```bash


cd /home/vologzhaninov_as/projects/morning_upload
docker build --progress=plain -t morning_upload:latest .


```

Запуск отдельно (отправляет обычные письма включённых процессов):

```bash


cd /home/vologzhaninov_as/projects/morning_upload
MORNING_IMAGE=morning_upload:latest bash ./run.sh


```

В начале лога должно быть `Запуск: morning_upload:latest`, а перед отправкой —
`Вложение: <имя с датой>.csv`. Этот же образ будет использовать существующий cron,
если его окружение не переопределяет `MORNING_IMAGE`.

УЭБ не пересылает повторно уже доставленный сегодня неизменившийся отчёт.
Eurostat не повторяет успешно завершённый месячный цикл. Такие пропуски сохраняются:
обновление не должно создавать дублирующиеся рассылки. Поэтому для этих источников
новое письмо может появиться только при очередном положенном запуске.
Не удаляйте состояния ради повторной отправки.

Ранее полученные письма не меняются. Проверять нужно вложение нового письма после
обновления. Схемы CSV, VPN БелАЭС и УЭБ, основной/резервный SMTP, cron и настройки
`gas_data_duty` этой правкой не меняются.
