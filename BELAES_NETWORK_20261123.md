# БелАЭС: AUTO с резервным SSH/VPN — 23.11.2026

БелАЭС сначала загружает страницу производственных показателей напрямую. При тайм-ауте,
ошибке соединения/HTTP или ответе без даты и двух значений выработки делает одну попытку
через SSH к VPN-серверу. После успешного запроса или ошибки соединение закрывается.
Следующий запуск снова начинает с прямого доступа.

В AUTO при исправном прямом доступе SSH не используется: не читаются SSH-ключи и
не требуется доступность VPN-сервера. УЭБ продолжает работать через свой обязательный
VPN-маршрут. Каждый процесс использует собственную HTTP-сессию и туннель.

## Конфигурация

Добавьте нужные строки из `BELAES_NETWORK_20261123.env.example` в **существующий** `.env`.
Минимальные настройки при уже работающем подключении УЭБ:

```dotenv
BELAES_NETWORK_MODE=auto
BELAES_URL=https://belaes.by/ru/proizvodstvennye-pokazateli.html
BELAES_CONNECT_TIMEOUT=10
BELAES_READ_TIMEOUT=30
BELAES_TUNNEL_MODE=dynamic
BELAES_REMOTE_PROXY_SCHEME=socks5h
```

При отсутствии этих строк действуют те же значения по умолчанию. Используйте полный
адрес страницы показателей; главная `https://belaes.by/` не содержит нужной таблицы.

| Переменная | Назначение |
|---|---|
| `BELAES_NETWORK_MODE` | `auto`, `direct` или `vpn`; регистр не имеет значения |
| `BELAES_URL` | Страница с исходной датой и выработкой двух блоков |
| `BELAES_CONNECT_TIMEOUT` | Таймаут установления HTTP-соединения, секунды |
| `BELAES_READ_TIMEOUT` | Таймаут ожидания данных HTTP, секунды |
| `BELAES_USER_AGENT` | По умолчанию Firefox 140.0 для Linux |
| `BELAES_TUNNEL_MODE` | `dynamic` (по умолчанию) либо `forward` |
| `BELAES_SSH_HOST`, `BELAES_SSH_USER`, `BELAES_SSH_PORT` | Адрес VPN-сервера и реквизиты SSH |
| `BELAES_SSH_KEY` | Путь к закрытому ключу на машине/в контейнере запуска |
| `BELAES_SSH_HOST_KEY_SHA256` | Доверенный отпечаток ключа VPN-сервера |
| `BELAES_SSH_KNOWN_HOSTS` | Файл known_hosts, если отпечаток не задан |
| `BELAES_SSH_CONNECT_TIMEOUT`, `BELAES_SSH_STARTUP_TIMEOUT` | Таймауты SSH |
| `BELAES_REMOTE_PROXY_PORT`, `BELAES_REMOTE_PROXY_SCHEME` | Для `forward` — порт прокси на удалённом сервере и его протокол |

Пустые/отсутствующие SSH-поля наследуют соответствующие `UEEX_*`. Можно использовать
тот же сервер, ключ и отпечаток, что уже настроены для УЭБ. Если для БелАЭС выбирается
другой сервер, задайте его собственные адрес, пользователя, ключ и отпечаток.

На ноутбуке путь `/root/.ssh/...` из серверной конфигурации недоступен обычному пользователю.
Для БелАЭС можно отдельно задать:

```dotenv
BELAES_SSH_KEY=/home/alexander/.ssh/id_ed25519
BELAES_SSH_KNOWN_HOSTS=/home/alexander/.ssh/known_hosts
```

Укажите фактическое имя своего закрытого ключа. Если локальный UEEX уже настроен и работает,
пустое `BELAES_SSH_KEY` использует его путь. Изменения BELAES_* не меняют настройки УЭБ.
Если задан `*_SSH_HOST_KEY_SHA256`, используется проверка отпечатка; иначе действует
проверка known_hosts. Автоматическое доверие неизвестному ключу не включается.

## Как используется VPN

В `dynamic` библиотека Paramiko создаёт SSH-соединение и временный локальный SOCKS5
на свободном порту. Это внутренний канал самого приложения, а не зависимость от ранее
включённого Hiddify или порта `127.0.0.1:12334`. SOCKS-прокси появляется автоматически
только на время запроса. Имя сайта разрешается на SSH-сервере (`socks5h`).

Трафик выходит через VPN-сервер, указанный в SSH-настройках. При `forward` трафик
дополнительно направляется в настроенный прокси на этом сервере. Удалённый порт и
протокол нужно указывать по действующей конфигурации, не подбирать из списка служебных портов.

Используются явные прокси-параметры с `Session.trust_env=False`: переменные системного
HTTP_PROXY/HTTPS_PROXY не превращают прямую попытку в скрытый прокси-запрос.
Проверка HTTPS-сертификатов сохранена. Отдельное сохранение cookies не требуется.
В requirements.txt уже есть requests, PySocks и Paramiko; новых зависимостей нет.

## Проверка и запуск

Замените файлы патча в корне проекта. Патч не содержит вашего `.env` и не меняет
`ENABLED_PROCESSES`, расписание cron, формат CSV или имена датированных вложений.
`gas_data_duty` для этого изменения обновлять не нужно.

На ноутбуке запустите `main.py` в PyCharm. Для проверки исключительно VPN-маршрута
временно задайте `BELAES_NETWORK_MODE=vpn`, затем верните `auto`.
Обычный запуск отправляет письма по прежним настройкам; отдельного CLI/preflight нет.

В логах видны прямой маршрут, причина переключения, создание SSH-прокси и успешная
проверка данных через VPN. Если оба маршрута не сработали, БелАЭС завершается с ошибкой
по прежней логике и не отправляет ошибочную выгрузку как успешную.

На сервере после замены файлов пересоберите образ:

```bash


cd /home/vologzhaninov_as/projects/morning_upload
docker build --progress=plain -t morning_upload:latest .


```

Cron продолжит запускать тот же `run.sh`.

## Проверки реализации

Проверен разбор реально полученного HTML страницы показателей БелАЭС до двух строк
с `source_date, fetch_date, unit, accumulated_production`.
В 11 контролируемых тестах проверены: исправный прямой доступ без SSH-настроек,
тайм-аут/403/страница блокировки и переход на SSH, принудительные DIRECT/VPN,
ошибки обоих маршрутов, закрытие ресурсов, наследование UEEX_* и отдельные BELAES_*.
Во время тестов реальные письма не отправляются. Подключение к вашему VPN-серверу
не выполнялось; этот участок проверяется запуском из вашей локальной сети.
