# СПбМТСБ и температура Цхинвала

Оба процесса добавлены в ENABLED_PROCESSES в main.py и выполняются при обычном запуске.
Для отключения закомментируйте соответствующую строку. Каждый процесс отправляет
отдельное письмо через common.mailer, с основным и резервным SMTP из существующего .env.

Добавьте настройки из NEW_PROCESSES_20261122.env.example в свой .env.
Пустые SPIMEX_SUCCESS_RECIPIENTS и TSKHINVAL_SUCCESS_RECIPIENTS используют RECIPIENTS.
Для уведомлений об ошибках используются *_ERROR_RECIPIENTS, затем ADMIN_RECIPIENTS
и список обычных получателей. Новые параметры не требуют изменения SMTP-настроек.

## СПбМТСБ

Источник — SPIMEX_URL, в комплекте ссылка пользователя для PCX1UGU036F.
Текст преобразуется в CSV с UTF-8 BOM и разделителем ;.
Поддерживаются разделители ;, tab, запятая и |, кодировки UTF-8, UTF-16 BOM и Windows-1251.
SPIMEX_SOURCE_DELIMITER=tab явно задаёт табуляцию, остальные разделители задаются символом.
Формат service.php подтверждён примером пользователя — 204 записи вида
2026-11-20;30383;null;5. Записи могут идти в одну строку через пробелы
либо разделяться переводами строки. В CSV каждая запись получает отдельную строку.
Заголовок — date;value;source_value_3;source_value_4. value — исходное второе поле.
Назначение полей source_value_3 и source_value_4 не устанавливается по их значениям.
Исходное null сохраняется текстом, значение 5 в последней записи тоже сохраняется.
Даты приводятся к YYYY-MM-DD. Все четыре поля проверяются при разборе.
Для других таблиц с заголовком исходные названия сохраняются.
При отсутствии заголовка в другом формате используются column_1, column_2 и т.д.
Старые заголовки column_1 … column_4 в накопленном четырёхколоночном CSV
автоматически заменяются новыми при следующем успешном запуске.
Колонка даты определяется по содержимому, при неоднозначности задайте SPIMEX_DATE_COLUMN.
Предполагается одна строка инструмента на дату. Конфликтующие строки за одну дату
останавливают процесс до проверки формата.

В output/spimex сохраняются:
- spimex_PCX1UGU036F_history.csv — вся полученная история, накопление между запусками.
- spimex_latest.csv — последние 30 строк по дате торгов, именно он вложен в письмо.

SPIMEX_LAST_ROWS регулирует число строк. Это строки торгов, выходные дни отдельно
не добавляются. Повторная дата обновляет строку в истории, старые даты сохраняются.
При смене code в URL используется другой исторический файл.
Письмо отправляется при каждом успешном запуске, в том числе при отсутствии свежих торгов.
HTTP-сбой или HTML вместо таблицы приводит к ошибке процесса и уведомлению.
Старые данные не выдаются за результат успешного скачивания.

Из среды разработки скачивание по ссылке возвращало HTTP 503.
Разбор, накопление и CSV-вложение проверены на полном тексте, присланном пользователем.
Пример содержит 204 записи за 02.02.2026 — 20.11.2026, последние 30 записей
охватывают 09.10.2026 — 20.11.2026. Сетевой доступ из серверного контейнера
проверяется при обычном запуске.

## Цхинвал

Источник — Open-Meteo / ECMWF IFS, daily=temperature_2m_mean, °C.
Используется готовая среднесуточная температура на высоте 2 м.
Координаты 42.22764, 43.96861, высота 874 м, часовой пояс Europe/Moscow.

Формат CSV сохранён по ранее согласованному проекту:

| Поле | Факт | Прогноз |
|---|---|---|
| region_name | Цхинвал | Цхинвал |
| parent_name | Южная Осетия | Южная Осетия |
| date | Дата суток | Дата выгрузки |
| fcst_date | Пусто | Дата прогнозируемых суток |
| temperature | Среднесуточная температура, °C | Среднесуточная температура, °C |
| value_type | Факт | Прогноз |

TSKHINVAL_PAST_DAYS=15 выбирает D-15 … D-1, всего 15 завершённых суток.
TSKHINVAL_FORECAST_DAYS_AHEAD=7 и TSKHINVAL_INCLUDE_TODAY=true дают сегодня
и следующие 7 дней, всего 8 строк, как в прежнем проекте.
TSKHINVAL_INCLUDE_TODAY=false выбирает только завтра … D+7, всего 7 строк.

Результат output/tskhinval/temperature_tskhinval.csv содержит 23 строки по умолчанию,
заменяется актуальным снимком и прикладывается к письму при каждом успешном запуске.
Порядок столбцов, значения Факт/Прогноз, формат дат и пустой fcst_date совместимы
с прежней загрузкой в PostgreSQL. Архив ранее выпущенных прогнозов здесь не накапливается.
Факт означает архивные расчётные значения ECMWF IFS за завершённые сутки.
Отсутствующие значения и неполный календарь считаются ошибкой источника.
Источник и атрибуция указаны в письме.

TSKHINVAL_API_KEY задаёт ключ платного API и автоматически переключает стандартные
URL на customer-*.open-meteo.com. Ключ скрыт в HTTP-логах.
Документация и условия https://open-meteo.com/en/docs/historical-weather-api,
https://open-meteo.com/en/docs, https://open-meteo.com/en/terms.

## Общие модули и запуск

common/csv_process.py — получение таблицы, блокировка пересечения запусков, атомарное
сохранение CSV и отправка письма. common/process_config.py — чтение настроек .env.
Загрузка таблиц, чтение истории и запись CSV выполняются через DataGateway.
common/http_client.py — существующий HTTP-клиент с повторами и Retry-After,
дополнен скрытием чувствительных query-параметров в логах.

SPIMEX_PROXY_URL и TSKHINVAL_PROXY_URL задаются независимо. Пусто означает прямой доступ.
Прокси УЭБ остаётся настройкой процесса УЭБ. В Docker адрес 127.0.0.1 относится к контейнеру,
поэтому для внешнего прокси укажите доступный контейнеру адрес.

Новых Python-зависимостей не требуется. Каталог output уже монтируется run.sh.
Для сервера замените файлы из патча в корне morning_upload и добавьте нужные настройки
в свой .env. Соберите morning_upload:latest существующим Dockerfile, затем запустите
bash ./run.sh либо дождитесь обычного cron. Запуск по расписанию включает новые процессы
через общий main.py.
